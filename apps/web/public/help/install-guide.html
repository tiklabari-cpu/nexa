Kurulum rehberi

SiyahTuş sohbet widget’ını sitenize eklemek için tek bir kod parçası yeterlidir. Bu sayfa kodun nereden alınacağını, nereye yapıştırılacağını ve çalıştığının nasıl anlaşılacağını anlatır. English version below.

  • Kodu alın ve yapıştırın
  • Çalıştığını doğrulayın
  • Google Tag Manager ile
  • iGaming platformunun içerik panelinde
  • JavaScript kapalı ziyaretçiler
  • Giriş yapmış üyeyi tanıtın (operatör imzalı kimlik)
  • Sorun giderme

1. Kodu alın ve yapıştırın

  1. Kurulum sihirbazında ya da Ayarlar → Kanallar → Web sitesi widget’ları bölümünde sitenizin alan adını girip Web sitesi ekle’ye basın. Alan adı aynı anda güvenilir alan adları listesine de eklenir.
  2. Çıkan kod kutusundaki Kodu kopyala düğmesine basın. Kodu siz yapıştırmayacaksanız Geliştiriciyi davet et ile e-posta programınızda hazır bir ileti açın.
  3. Kodu sitenizin her sayfasında, kapanış </body> etiketinden hemen önce yapıştırın. Kod şuna benzer: 
<!-- SiyahTuş widget -->
<script>
  window.__siyahtus = { organizationId: "…", widgetOrigin: "https://…" };
</script>
<script async src="https://…/loader.js"></script>
<noscript><a href="https://…/chat.html?organization_id=…">Bizimle sohbet edin</a></noscript>

Kodu olduğu gibi yapıştırın; satırları değiştirmeyin. Görünümü (renk, konum, dil) kodu değiştirmeden Ayarlar → Kanallar → Widget görünümü’nden ayarlarsınız.

2. Çalıştığını doğrulayın

Siteniz yayındayken herhangi bir sayfayı bir kez açın. Widget ilk kez yüklendiğinde sitenin durumu “İlk mesaj bekleniyor”dan “Bağlı”’ya döner; sihirbazda aynı satır kendiliğinden güncellenir, sayfayı yenilemeniz gerekmez. Durumu istediğiniz zaman Ayarlar → Kanallar → Web sitesi widget’ları bölümünden görürsünüz.

3. Google Tag Manager ile

  1. Tag Manager’da Etiketler → Yeni deyin, tür olarak Özel HTML seçin.
  2. HTML alanına SiyahTuş kodunun tamamını yapıştırın (<script> ve <noscript> satırları dahil).
  3. Tetikleyici olarak Tüm Sayfalar’ı seçin, etiketi adlandırıp kaydedin.
  4. Önizle ile sitenizde etiketin tetiklendiğini görün, sonra Gönder ile yayımlayın.

Tag Manager, <noscript> satırını sayfaya her zaman koymayabilir. Bu yedek bağlantı için zorunlu değildir; widget’ın kendisi <script> satırlarıyla çalışır.

4. iGaming platformunun içerik panelinde

BetConstruct, EveryMatrix gibi platformlar sitenin şablonuna kod eklemek için bir “özel script”, “özel HTML” ya da “altbilgi kodu” alanı sunar. Menü adları platforma ve sürüme göre değişir; adımlar aynıdır:

  1. İçerik / site yönetim panelinde tüm sayfalarda gösterilen altbilgi (footer) ya da sayfa sonu kod alanını bulun.
  2. SiyahTuş kodunun tamamını bu alana yapıştırıp kaydedin ve yayımlayın.
  3. Önbellek ya da CDN kullanılıyorsa temizleyin, sonra sitenizi açıp doğrulayın.

Bazı platformlar özel script alanında async özniteliğini kaldırır ya da <script> etiketlerini süzer. Widget yine de çalışır, yalnızca geç yüklenebilir. Hiç yüklenmiyorsa platform desteğinden “üçüncü taraf script” izni isteyin; siteyi bozmadan eklenebilen bir alan yoksa bir sonraki bölümdeki barındırılan sohbet sayfası bağlantısını sitenize düğme olarak koyabilirsiniz.

5. JavaScript kapalı ziyaretçiler

Kodun sonundaki <noscript> satırı, tarayıcısında JavaScript kapalı ya da bir reklam engelleyici yüzünden widget’ı göremeyen ziyaretçiye “Bizimle sohbet edin” bağlantısı gösterir. Bağlantı, SiyahTuş’un barındırdığı tam sayfa sohbet ekranını sizin çalışma alanınızla açar; bu sayfanın ayrıca bir güvenilir alan adı tanımı gerektirmez. Bağlantı metni, kodu kopyaladığınız andaki widget dilinizle yazılır. Daha önce yapıştırdığınız kodlar değişmez; yedek bağlantıyı istiyorsanız güncel kodu yeniden kopyalayıp yapıştırın.

6. Giriş yapmış üyeyi tanıtın (operatör imzalı kimlik)

İsteğe bağlıdır. Siteniz hangi üyenin giriş yaptığını bilir; sunucunuz o üyenin numarasını imzalayıp widget’a verirse oyuncu her cihazda aynı doğrulanmış üye olur ve ajanlarınız onu “Doğrulanmış üye” rozetiyle görür. İmza gelmezse bugünkü tanıma sürer: ziyaretçi tarayıcısından tanınır, gerisini ajan onaylar.

  1. Ayarlar → Güvenlik → Üye tanıma ekranında “Operatör imzalı kimlik” kartından Gizli anahtar üret’e basın. Anahtar yalnızca bir kez gösterilir; kopyalayıp sunucunuzun ortam değişkenine koyun (ör. SIYAHTUS_IDENTITY_SECRET), sonra anahtarı açın.
  2. Sunucunuz giriş yapmış üye için her sayfada bir imza üretir: anahtar gizli anahtarın kendisi olan HMAC-SHA256, küçük harfli onaltılık, şu satırlar üzerinden (olmayan kullanıcı adı ya da e-posta boş satırdır; hiçbir alanda satır sonu olamaz): siyahtus-identify-v1\n<user_id>\n<username>\n<email>\n<ts>. user_id metindir: sayısal üye numarasını da metne çevirip imzalayın ve öyle gönderin — sayı olarak giden kimlik yok sayılır. ts saniye cinsinden şimdiki Unix zamanıdır; beş dakikadan eski ya da bir kez kullanılmış imza yok sayılır. İmzalı sonucu yalnızca o üyeye giden yanıta koyun — bir önbelleğin ya da CDN’in başka bir ziyaretçiye sunabileceği sayfaya asla.
  3. Sayfa yüklendikten sonra sonucu siyahtus('identify', …) ile verin. Tek sayfalık sitede bunu üye giriş yaptıktan hemen sonra yapın; üye çıkış yaptığında siyahtus('logout') çağırın.

Node.js

const crypto = require('node:crypto');

function siyahtusIdentity(user) {
  const id = String(user.id);
  const ts = Math.floor(Date.now() / 1000);
  const message = ['siyahtus-identify-v1', id, user.username || '', user.email || '', String(ts)].join('\n');
  const user_hash = crypto
    .createHmac('sha256', process.env.SIYAHTUS_IDENTITY_SECRET)
    .update(message)
    .digest('hex');
  return { user_id: id, username: user.username || '', email: user.email || '', ts, user_hash };
}

PHP

<?php
function siyahtus_identity(array $user): array {
    $id = (string) $user['id'];
    $ts = time();
    $message = implode("\n", ['siyahtus-identify-v1', $id, $user['username'] ?? '', $user['email'] ?? '', (string) $ts]);
    $hash = hash_hmac('sha256', $message, getenv('SIYAHTUS_IDENTITY_SECRET'));
    return ['user_id' => $id, 'username' => $user['username'] ?? '', 'email' => $user['email'] ?? '', 'ts' => $ts, 'user_hash' => $hash];
}

Sayfada

<script>
  window.addEventListener('load', function () {
    siyahtus('identify', <?= json_encode(siyahtus_identity($user), JSON_HEX_TAG | JSON_HEX_AMP) ?>);
  });
</script>

Gizli anahtar asla tarayıcıya konmaz. İmzayı yalnızca sunucunuz üretir; anahtarı bir web sayfasına, bir betiğe, bir etiket yöneticisine ya da ziyaretçinin indirebileceği bir uygulamaya koymayın — anahtara sahip olan herkes istediği üye olarak giriş yapabilir. Anahtar sızdıysa aynı ekranda geçiş süresini 0 yapıp yenisini üretin. Ayarlar ekranındaki “Son 7 gündeki imzalar” sayacı kaç imzanın doğrulandığını ve yok sayılanların nedenini gösterir; yanlış imza oyuncuya hiçbir zaman hata olarak görünmez.

7. Sorun giderme

  • Durum “İlk mesaj bekleniyor”da kalıyor. Kodun sayfada gerçekten bulunduğunu tarayıcıda “sayfa kaynağını görüntüle” ile kontrol edin; sonra sitenin alan adının Ayarlar’daki Güvenilir alan adları listesinde olduğundan emin olun.
  • Widget görünmüyor. Sitenizin İçerik Güvenlik Politikası (Content-Security-Policy) script-src ve frame-src için kodun widgetOrigin adresine izin vermelidir.
  • Alan adı bir alt alan adı. www.ornek.com ile ornek.com ayrı sayılır; sitenizin gerçekten açıldığı adı ekleyin.

Installation guide

One snippet puts the SiyahTuş chat widget on your site. This page covers where to get it, where to paste it and how to tell it works.

1. Get the code and paste it

  1. In the setup wizard, or under Settings → Channels → Website widgets, enter your site’s domain and press Add website. The domain is added to your trusted domains at the same time.
  2. Press Copy code in the code box. If someone else will paste it, Invite developer opens a ready-made message in your mail program.
  3. Paste it on every page, immediately before the closing </body> tag, exactly as copied. Look and feel (colour, position, language) is set under Settings → Channels → Widget appearance without touching the code.

2. Check that it works

Open any page of your live site once. The first time the widget loads, the site’s status changes from “Waiting for first message” to “Connected”; in the wizard the same line updates by itself.

3. With Google Tag Manager

  1. Create a tag of type Custom HTML.
  2. Paste the whole snippet, <script> and <noscript> lines included.
  3. Trigger it on All Pages, save, check it fires in Preview, then Submit.

Tag Manager may not place the <noscript> line on the page. That is fine: the widget itself runs from the <script> lines.

4. In an iGaming platform’s content panel

Platforms such as BetConstruct or EveryMatrix offer a “custom script”, “custom HTML” or “footer code” field. Names differ by platform and version; the steps do not: find the footer field shown on all pages, paste the whole snippet, save and publish, clear any cache or CDN, then check.

Some platforms strip async or filter <script> tags in that field. The widget then loads later, or not at all — ask the platform to allow a third-party script. If no safe field exists, put the hosted chat page link on your site as a button instead.

5. Visitors with JavaScript off

The <noscript> line at the end of the snippet shows a “Chat with us” link to visitors whose browser has JavaScript off, or whose ad blocker hides the widget. It opens SiyahTuş’s hosted full-page chat for your workspace; that page needs no trusted-domain entry. The link text follows the widget language at the moment you copy the code. Snippets you pasted earlier do not change — copy and paste the current one if you want the fallback link.

6. Recognise logged-in members (operator-signed identity)

Optional. Your site knows which member is logged in; when your server signs that member’s id and hands it to the widget, the player is the same verified member on every device, and your agents see them with a “Verified member” badge. Without a signature today’s recognition carries on: the visitor is recognised by their browser, and agents confirm the rest.

  1. Under Settings → Security → Member recognition, press Issue a secret on the “Operator-signed identity” card. It is shown once: copy it into your server’s environment (e.g. SIYAHTUS_IDENTITY_SECRET), then switch the feature on.
  2. For the logged-in member, your server signs on every page: HMAC-SHA256 keyed with the secret itself, lowercase hex, over these lines (an absent username or e-mail is an empty line; no field may contain a line break): siyahtus-identify-v1\n<user_id>\n<username>\n<email>\n<ts>. user_id is text: turn a numeric member id into a string before you sign and send it — an id sent as a number is ignored. ts is the current Unix time in seconds; a signature older than five minutes, or used once already, is ignored. Put the signed result only into the response that goes to that member — never into a page a cache or CDN could serve to another visitor.
  3. Once the page has loaded, hand the result to siyahtus('identify', …). In a single-page site do it right after the member signs in; when they sign out, call siyahtus('logout').

The Node.js, PHP and page examples above apply unchanged.

The secret never goes in a browser. Only your server signs. Never put the secret in a web page, a script, a tag manager or an app a visitor can download — anyone who has it can sign in as any member. If it leaked, issue a new one on the same screen with a grace period of 0. The “Signatures in the last 7 days” count on the settings screen says how many were verified and why the others were ignored; a wrong signature is never shown to the player as an error.

7. Troubleshooting

  • Stuck on “Waiting for first message”. View the page source to confirm the snippet is there, then make sure the site’s domain is in Trusted domains in Settings.
  • Widget not visible. Your site’s Content-Security-Policy must allow the snippet’s widgetOrigin in script-src and frame-src.
  • Subdomains. www.example.com and example.com are different names; add the one your site is served on.
